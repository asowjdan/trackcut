# 1일차 작업일지 (2026-11-13)

## 진행상황

기획서를 바탕으로 편집기 **trackcut**을 Rust로 만들기 시작했다. 하루 동안 코어, 명령줄 도구, 편집 화면, 내보내기, 소리 재생, 마우스 편집, 속성 패널, 재생 속도·화면 자르기, 여러 파일 이어 붙이기까지 동작하는 상태가 됐다. 테스트 44개가 통과한다.

### 결정한 것

| 결정 | 이유 |
|---|---|
| 화면까지 전부 Rust(egui)로 만든다 | 프로그램 성능을 우선한다. 화면을 GPU로 직접 그리고, MCP도 한 프로세스에서 편집 상태를 직접 다룬다. |
| 공개 저장소로 작업하고, 개인정보·컴퓨터 정보가 들어간 변경은 자동 거절한다 | 커밋 훅과 CI에서 `scripts/check-private.sh`가 검사한다. |
| 프로젝트 이름은 trackcut | 트랙 + 컷 |
| 시간은 flick(1/705,600,000초) 정수로 계산한다 | 60fps 프레임과 48kHz 샘플이 정수로 떨어져 오차가 없다. |
| 영상 디코딩과 내보내기는 `ffmpeg` 프로세스를 쓴다 | FFmpeg 라이브러리를 직접 링크하지 않아 빌드가 단순하다. 느리면 나중에 바꾼다. |
| 빌드 출력은 영문 경로에 둔다 | Windows GNU 도구(ld, dlltool)가 한글 경로의 파일을 열지 못한다. 소스와 미디어는 한글 경로여도 된다. |

### 실제 샘플 영상에서 찾아 고친 것

- OBS가 파일 끝에 화면에 나오지 않는 "버림" 패킷을 하나 남긴다. 이것을 프레임으로 세고 있었다.
- 프레임이 빠진 녹화본을 "프레임 간격 일정"으로 잘못 판정할 수 있었다.
- OBS가 자동으로 붙이는 트랙 이름(`OBS Audio Handler`)을 이름표로 취급하고 있었다.

## 마지막 작업

사용자 요청으로 화면 구성과 편집 방식을 바꿨다.

- **화면 자르기**: 숫자 입력 대신 미리보기에서 빨간 테두리의 손잡이 8개를 끌어 자른다(`app/panels.rs`).
- **구역**: 시작점·끝점 하나 대신 구역을 여러 개 둔다. 우클릭 메뉴로 구역 분할, 구역 삭제, 표시 지우기를 한다. 분할은 구역의 양 끝에서 나누는 것만 남기고 재생 위치 기준 분할(S 키)은 없앴다. 구역은 화면 상태라서 프로젝트 파일에 저장하지 않는다.
- **클립 제목과 순서**: 클립 위에 "영상 N · 분할 K" 제목 띠를 그린다. `Project::swap_with_neighbor`로 이웃 클립과 자리를 바꾼다(왼쪽 패널 "순서" 탭, 우클릭 메뉴).
- **상단 메뉴바**: 왼쪽에 저장·내보내기·되돌리기, 가운데에 재생·프레임 이동, 오른쪽에 지금 위치.
- **왼쪽 패널**: 선택한 것이 영상이면 영상 편집(속도, 자르기, 출력 해상도), 오디오면 오디오 편집(볼륨, 소리 보정)을 보여 준다.
- **소리 보정**: `fx.rs`가 FFmpeg 필터(`highpass`, `afftdn`, `bass`, `equalizer`, `treble`)로 새 FLAC 파일을 만들고, `Project::add_processed_track`이 원본 바로 아래 새 트랙에 올린다. 원본 트랙은 음소거만 한다.
- 확인: 테스트 48개, 영상·오디오 선택 화면과 구역·자르기 테두리 화면 캡처. 마우스 조작(손잡이 끌기, 우클릭 메뉴, 순서 바꾸기 버튼)과 보정한 소리를 듣는 것은 해 보지 못했다.
- 아직 없는 것: AI 업스케일링, TTS 변환(쓸 엔진을 사용자와 정해야 한다).

사용자 요청 다섯 가지를 넣었다.

- **미리보기 화질**: 540p로 줄여 디코딩하던 것을 원본 해상도 기본으로 바꿨다. 개발용 빌드에서도 끊기지 않게 외부 라이브러리는 최적화해서 빌드한다(`Cargo.toml`의 `profile.dev.package`).
- **재생 속도·화면 자르기**: `Clip`에 `speed_pct`, `crop`을 추가했다. 타임라인 길이는 원본 길이 ÷ 속도이고, 분할·트림·구간 삭제는 `Clip::src_at`으로 원본 위치를 계산한다. 속도를 바꾸면 뒤쪽 클립이 밀리거나 당겨진다. 소리는 미리듣기(선형 보간)와 내보내기(`asetrate`) 모두 음높이가 함께 바뀐다.
- **왼쪽 속성 패널**: `app/inspector.rs`. 숫자 칸을 연달아 고친 것은 `History::apply_keyed`로 Undo 한 단계로 묶는다. 믹서 볼륨 슬라이더도 이제 되돌릴 수 있다.
- **구간 지정**: 타임라인을 두 번 누르면 누른 곳 양쪽 60px에 시작점·끝점이 놓이고, 선이나 눈금의 손잡이를 끌어 조절한다.
- **여러 파일**: `Project::append_media`가 타임라인 끝(프레임 경계)에 기존 트랙을 재사용해 놓는다. 창에 여러 파일을 놓거나 실행 인자로 여러 개를 주면 차례로 붙는다.

그 전에 클립 선택과 드래그 편집을 화면에 넣었다(다음 작업 1번).

- 클립을 누르면 선택되고, 가운데를 끌면 이동, 양 끝 6px 안쪽을 끌면 트림이다. 눈금이나 빈 곳을 끌면 재생 위치가 움직인다.
- 끄는 동안에는 시작할 때의 상태에서 매번 다시 계산해 미리 보여 주고, 놓을 때 Undo 한 단계로 남긴다. 겹쳐서 놓을 수 없는 위치에서는 마지막으로 가능했던 위치에 머문다.
- 트랙 이름을 두 번 누르면 그 자리에서 이름을 바꾼다. M은 선택한 트랙 음소거, U는 선택한 클립의 연결 해제다.
- 화면 확인용 실행 인자 `--select 클립순번`, `--pos x,y`를 추가했다.
- 선택 표시(흰 테두리, 연결된 클립의 옅은 테두리, 트랙 이름 강조)는 화면 캡처로 확인했다.

그 전에 내보내기, 소리 재생, 파형을 구현하고 기획서 요구사항과 대조해 점검했다.

- 샘플영상 폴더의 OBS 녹화본 2개(1080p60, 16초와 8초)로 확인했다. 둘 다 오디오 트랙이 1개다.
- 16초 샘플에서 2.5초를 지워 내보낸 결과가 정확히 815프레임이었고, 원본은 바뀌지 않았다.
- 샘플을 재생 상태로 띄워, 재생 위치가 소리 출력 시계를 따라 진행하는 것을 캡처로 확인했다.

### 아직 확인하지 못한 것

- 소리를 귀로 들어 보는 확인 (볼륨을 최소로 낮춘 상태로만 돌렸다)
- 단축키(M, U 포함), 휠 확대·축소를 실제로 눌러 보는 확인
- 마우스로 클립을 끌어 이동·트림하는 것, 트랙 이름을 두 번 눌러 바꾸는 것 (계산은 테스트했고 마우스 조작은 해 보지 못했다)
- 타임라인을 두 번 눌러 구간을 만들고 선을 끄는 것, 속성 패널의 숫자 칸을 끌거나 입력하는 것, 창에 파일을 더 끌어다 놓는 것
- 원본 화질 미리보기가 재생 중에 끊기지 않는지, 속도를 바꾼 클립의 소리
- 오디오 6트랙 녹화본 (샘플은 1트랙)
- 프레임 이동 0.1초 이내, 30~40분 파일 처리 속도

## 다음 작업

우선순위 순서다.

1. **자동 저장**과 불러오기 진행률 표시
2. **노이즈 제거와 음성 보정**: `afftdn`, `arnndn`, `highpass`, `agate`, `loudnorm`, 컴프레서 등. 미리 처리해 캐시하고 전후 비교(A/B)를 넣는다.
3. **여러 영상 트랙 합성**, 클립 복사·붙여넣기, 여러 클립 선택
4. **전환 효과**: 내보내기는 `xfade`, 미리보기는 셰이더
5. **스마트 렌더**: 손대지 않은 구간은 원본을 그대로 복사. FFV1, MKV + FLAC 내보내기 옵션.
6. **AI 조작(MCP)**: 편집기 안의 MCP 서버와 작업 표시 화면
7. **OBS 스크립트**: 녹화가 끝나면 자동으로 이름표 넣기
8. 썸네일 띠, 음성 변조, TTS

### 알아둘 한계

- 여러 클립을 한꺼번에 선택할 수 없고, 푼 연결을 화면에서 다시 묶을 수 없다(되돌리기로만).
- 속도를 바꾸면 소리의 음높이도 함께 바뀐다(음높이 유지는 아직 없다).
- 해상도가 다른 파일을 이어 붙이면 첫 파일의 해상도에 맞춰 비율을 지킨 채 채운다.
- 파일 추가를 되돌려도 프로젝트 파일의 미디어 목록에는 남는다(화면에는 보이지 않는다).
- 구역은 저장되지 않는다. 프로그램을 다시 열면 사라진다.
- 소리 보정은 트랙 전체에 한 번에 적용한다. 보정한 뒤 설정을 바꾸려면 새 트랙을 다시 만든다.
- 출력 해상도 변경은 되돌리기에 들어가지 않는다.
- 내보내기는 전체를 다시 인코딩한다.
- 영상 트랙이 여러 개면 첫 번째만 내보낸다.
- 클립 조각이 약 200개를 넘으면 내보내기 명령이 Windows 명령줄 길이 제한에 걸릴 수 있다.
- 모노 소리는 스테레오로 펼칠 때 3dB 작아진다(미리듣기와 내보내기가 같다).
- 긴 녹화본은 오디오 캐시가 트랙당 약 460MB(40분 기준) 디스크를 쓴다.
