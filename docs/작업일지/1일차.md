# 1일차 작업일지 (2026-11-13)

## 진행상황

기획서를 바탕으로 편집기 **trackcut**을 Rust로 만들기 시작했다. 하루 동안 코어, 명령줄 도구, 편집 화면, 내보내기, 소리 재생까지 동작하는 상태가 됐다. 테스트 35개와 GitHub CI가 통과한다.

### 결정한 것

| 결정 | 이유 |
|---|---|
| 화면까지 전부 Rust(egui)로 만든다 | 프로그램 성능을 우선한다. 화면을 GPU로 직접 그리고, MCP도 한 프로세스에서 편집 상태를 직접 다룬다. |
| 공개 저장소로 작업하고, 개인정보·컴퓨터 정보가 들어간 변경은 자동 거절한다 | 커밋 훅과 CI에서 `scripts/check-private.sh`가 검사한다. |
| 프로젝트 이름은 trackcut | 트랙 + 컷 |
| 시간은 flick(1/705,600,000초) 정수로 계산한다 | 60fps 프레임과 48kHz 샘플이 정수로 떨어져 오차가 없다. |
| 영상 디코딩과 내보내기는 `ffmpeg` 프로세스를 쓴다 | FFmpeg 라이브러리를 직접 링크하지 않아 빌드가 단순하다. 느리면 나중에 바꾼다. |
| 빌드 출력은 영문 경로에 둔다 | Windows GNU 도구(ld, dlltool)가 한글 경로의 파일을 열지 못한다. 소스와 미디어는 한글 경로여도 된다. |

### 만든 것

| 영역 | 내용 | 확인 방법 |
|---|---|---|
| 미디어 분석 | 트랙 수, 실제 프레임 시각, 키프레임, 트랙별 시작 시각. VFR 지원 | 단위 테스트, 실제 OBS 샘플 |
| 트랙 이름표 | 다시 인코딩 없이 이름표를 넣은 새 파일과 `*.tracks.json` | 실제 ffmpeg 테스트 |
| 타임라인 모델 | 영상과 오디오가 연결된 단일 타임라인, 시작 시각 차이 보정 | 단위 테스트 |
| 편집 동작 | 분할, 구간 삭제, 트림, 이동, 연결/해제, 볼륨·음소거·솔로, Undo/Redo | 단위 테스트 15개 |
| 프레임 정확한 디코더 | 요청한 프레임 번호와 받은 프레임이 일치 | 프레임 번호를 새긴 영상으로 테스트 |
| 편집 화면 | 위쪽 미리보기, 아래쪽 타임라인, 오른쪽 믹서, 단축키, 휠 확대·축소 | 화면 캡처 |
| 내보내기 | 섞어서 하나로, 다중 트랙, 트랙별 WAV. NVENC 우선, 진행률·취소 | 내보낸 파일을 프레임별로 되읽는 테스트, 실제 샘플(965 → 815프레임) |
| 소리 재생 | 캐시한 PCM을 실시간으로 섞어 출력, 화면이 소리 위치를 따라감 | 섞기 단위 테스트, 재생 중 화면 캡처 |
| 파형 | 10ms 단위 피크를 타임라인 클립에 표시 | 실제 ffmpeg 테스트, 화면 캡처 |
| 개인정보 검사 | 사용자 폴더 경로, 이메일, IP, 토큰, 컴퓨터 이름, 녹화본 파일 거절 | 시험용 파일로 거절 확인 |

### 실제 샘플 영상에서 찾아 고친 것

- OBS가 파일 끝에 화면에 나오지 않는 "버림" 패킷을 하나 남긴다. 이것을 프레임으로 세고 있었다.
- 프레임이 빠진 녹화본을 "프레임 간격 일정"으로 잘못 판정할 수 있었다.
- OBS가 자동으로 붙이는 트랙 이름(`OBS Audio Handler`)을 이름표로 취급하고 있었다.

## 마지막 작업

내보내기, 소리 재생, 파형을 구현하고 기획서 요구사항과 대조해 점검했다.

- 샘플영상 폴더의 OBS 녹화본 2개(1080p60, 16초와 8초)로 확인했다. 둘 다 오디오 트랙이 1개다.
- 16초 샘플에서 2.5초를 지워 내보낸 결과가 정확히 815프레임이었고, 원본은 바뀌지 않았다.
- 샘플을 재생 상태로 띄워, 재생 위치가 소리 출력 시계를 따라 진행하는 것을 캡처로 확인했다.

### 아직 확인하지 못한 것

- 소리를 귀로 들어 보는 확인 (볼륨을 최소로 낮춘 상태로만 돌렸다)
- 단축키, 휠 확대·축소, 타임라인 드래그를 실제로 눌러 보는 확인
- 오디오 6트랙 녹화본 (샘플은 1트랙)
- 프레임 이동 0.1초 이내, 30~40분 파일 처리 속도

## 다음 작업

우선순위 순서다.

1. **클립 선택과 드래그 편집**: 클립·트랙 선택, 마우스로 트림·이동, 연결 해제, 트랙 이름 바꾸기, M 키 음소거. 코어에는 이미 있고 화면에만 없다.
2. **자동 저장**과 불러오기 진행률 표시
3. **노이즈 제거와 음성 보정**: `afftdn`, `arnndn`, `highpass`, `agate`, `loudnorm`, 컴프레서 등. 미리 처리해 캐시하고 전후 비교(A/B)를 넣는다.
4. **다른 파일 추가**: 화면에서 파일을 타임라인에 추가(지금은 새 프로젝트로 열린다). 여러 영상 트랙 합성.
5. **전환 효과**: 내보내기는 `xfade`, 미리보기는 셰이더
6. **스마트 렌더**: 손대지 않은 구간은 원본을 그대로 복사. FFV1, MKV + FLAC 내보내기 옵션.
7. **AI 조작(MCP)**: 편집기 안의 MCP 서버와 작업 표시 화면
8. **OBS 스크립트**: 녹화가 끝나면 자동으로 이름표 넣기
9. 썸네일 띠, 음성 변조, TTS

### 알아둘 한계

- 내보내기는 전체를 다시 인코딩한다.
- 영상 트랙이 여러 개면 첫 번째만 내보낸다.
- 클립 조각이 약 200개를 넘으면 내보내기 명령이 Windows 명령줄 길이 제한에 걸릴 수 있다.
- 모노 소리는 스테레오로 펼칠 때 3dB 작아진다(미리듣기와 내보내기가 같다).
- 긴 녹화본은 오디오 캐시가 트랙당 약 460MB(40분 기준) 디스크를 쓴다.
